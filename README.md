# GRM — Garry's Mod RP-сборка (DrStrasse)

> Передача дел новой сессии агента: читать **`HANDOVER.md`** (ветка
> `arena/019f6cb8-drstrasse` — актуальный код; master — старый пустой снапшот).

Набор Lua-модулей для Garry's Mod: фракции, экономика, инвентарь, логистика,
завод полного цикла, видеонаблюдение (CCTV), сигнализации, система розыска, двери,
дверные ключи `ds_key_swep`, FFD Fading Door, FFD Keypad с 3D2D экраном, полицейский таран `ds_battering_ram`, QTE-отмычка `ds_lockpick`,
телефонная связь, стамина, RP-чат и персистентность. Все модули общаются через
глобальный namespace `GRM` и глобальную таблицу `Factions`.

## Установка

Скопировать содержимое `lua/` в `garrysmod/addons/grm/lua/`
(или прямо в `garrysmod/lua/`). Файлы в `lua/autorun/` загружаются
автоматически на сервере и клиенте.

**Начиная с Кода 88 (мобильные телефоны)** вместе с `lua/` нужно
скопировать и папки `models/ivancorn/` + `materials/models/ivancorn/`
(модели трубок GTA IV by ivancorn) — иначе мобильные будут ERROR.
Готовый `dist/grm_single_addon.zip`/`grm_full_code.zip` уже содержит
всё тремя папками (lua, models, materials).

### Vehicle Dealer spawn zones 2026-07-30

- Добавлен инструмент **GRM: Зона выдачи транспорта** (`grm_vehicle_spawn_zone`) по схеме зоны тюрьмы. Встаньте рядом с нужным дилером: ЛКМ — первый угол, ПКМ — противоположный угол и сохранение, R — удалить зону.
- Зона отображается только суперадмину с активным инструментом: зелёный wireframe box, название дилера и синяя линия направления выдачи. Минимальный размер — 120×120 юнитов.
- Дилер сохраняет `hasSpawnZone`, `spawnZoneMin`, `spawnZoneMax` и угол транспорта в своей map-базе и восстанавливает их после рестарта/cleanup.
- При выдаче система проверяет центр и четыре внутренние точки зоны, прижимает кандидата к земле и выполняет `TraceHull` размером с транспорт. Машина не создаётся поверх стены, игрока или другой машины; если площадка занята, игрок получает явное сообщение «Зона выдачи занята».
- Инструмент добавлен в единый каталог GRM Стройка+. Старую одиночную точку дилера оставили как compatibility fallback для уже настроенных карт.

- В `/grm_admin → Меню` добавлены прямые ярлыки «База розыска» и «Доступ к розыску».

### Inventory 3D accessory previews 2026-07-30

- Аксессуары в сетке Inventory больше не отображаются общей иконкой человечка. Для предметов с `accessoryID` читается авторитетная `.mdl` из каталога и создаётся маленький `DModelPanel` прямо внутри ячейки.
- Модель автоматически центрируется по `GetRenderBounds`, подбирает дистанцию камеры и медленно вращается. Поддерживаются модели разных размеров из любых смонтированных аддонов.
- 3D-предпросмотр также используется в правой панели описания и в полупрозрачном Drag&Drop-призраке. Обычные предметы и оружие сохраняют старые icon16.
- Preview отключает ввод мыши/клавиатуры, поэтому не ломает выделение, ПКМ, перетаскивание в equipment slot и tooltip ячейки.

### Inventory accessory preview framing hotfix 2026-07-31

- Исправлены длинные и смещённые модели аксессуаров, которые при вращении выходили за границы ячейки. Preview теперь вычисляет центр и bounding sphere по `GetRenderBounds`, компенсирует смещённый model origin при каждом угле и вращает геометрию строго вокруг визуального центра.
- Камера рассчитывается через радиус сферы и FOV с запасом 28%, поэтому трубки, респираторы, рюкзаки и модели нестандартных пропорций полностью помещаются при любом угле.
- Скорость вращения уменьшена: 12°/с в ячейке и Drag&Drop, 10°/с в подробном просмотре. Добавлено нейтральное освещение сверху и спереди.

### Customization transform persistence v2 hotfix 2026-07-31

- Положение аксессуаров переведено с JSON-map на versioned array schema: `{version=2, records=[{key, slots, profiles}]}`. CharacterKey больше не используется как потенциально проблемный JSON-ключ верхнего уровня.
- Добавлены постоянные transform-профили `[CharacterKey][accessoryID]`. Position/Angles/Scale обновляются при «Сохранить положение» и «Готово», переживают переподключение и рестарт, а после снятия/повторного надевания применяются снова.
- Старый формат `CharacterKey -> slots` мигрирует автоматически в v2 и одновременно создаёт profiles для уже надетых предметов.
- Перед каждой записью создаётся `.backup`; при битом/пустом основном JSON загрузчик пробует backup и сообщает восстановление в серверную консоль. После записи выполняется read-back и повторный JSON parse.
