## 2. Что это за проект

**GRM** — набор Lua-модулей для roleplay-серверов Garry's Mod: фракции,
экономика, инвентарь, документы, служебные компьютеры, розыск и штрафы,
транспорт, логистика, маскировка, комендантский час, CCTV, прослушка,
пожарная служба, биржа труда, телефон и многое другое.

Все модули общаются через глобальный namespace `GRM` и глобальную таблицу
`Factions`. Общий фундамент — **GRM Core** (см. `ARCHITECTURE.md` § «GRM Core»).

## 4. Правила работы (стоящие приказы владельца)

1. Язык общения — **русский**; по делу, без воды.
2. **Код не слать в чат** — только коммиты / архивы / ссылки + проза.
3. После любой правки Lua: валидация синтаксиса → пересборка архивов
   (`python3 tools/build_dist.py`) → обновление README/CHANGELOG → **commit+push сразу**.
   Песочница Arena **откатывает файлы прямо посреди хода** — не откладывай пуш.
4. Следующий свободный номер модуля смотри в таблице README (последний «Код 108»).
5. Не работать от `master` — он почти пустой снапшот пра-истории.

## 5. Как работать с ветками (важно!)

- Рабочая ветка сессии Arena фиксирована (например `arena/01a00fa9-drstrasse`).
- **Master не трогать.**
- Чистая сборка для владельца живёт в ветке **`release/GRMRP`**.
- Если git-история после отката расходится:
  ```bash
  git fetch origin <ветка>
  git reset --mixed FETCH_HEAD   # mixed, не hard — рабочее дерево сохранится
  ```

## 6. Пересборка архивов (dist/)

```bash
python3 tools/build_dist.py
```

Собирает (описание — в `build_dist.py`):
- `grm_single_addon.zip` — единый аддон, файлы под префиксом `grm/`;
- `grm_full_code.zip` — то же без префикса;
- `grm_economy.zip` — изолированный экономический срез (список файлов — в скрипте);
- `grm_fix_hud_tab_currency.zip` — точечный фикс HUD/TAB/валюты;
- `grm_fire_addon.zip` — пожарный аддон (собирается отдельно из `addons/grm_fire/`).

## 7. Валидация Lua (обязательна после правок)

В песочнице каждый ход нужно ставить парсер заново:
```bash
pip install -q --break-system-packages luaparser
```
Прогнать AST-валидацию всех файлов (пример — в `tools/luatest/`), либо для
быстрой проверки конкретного файла использовать `luaparser`/LuaJIT.

**ВАЖНО — LuaJIT-особенности:**
- `goto`, `continue` — расширения LuaJIT GMod; обычный `luaparser` на них падает
  (ложные ошибки). Реальный LuaJIT их понимает.
- **`goto` как голый ключ таблицы (`{ goto = ... }`) — это СИНТАКС-ОШИБКА**
  в LuaJIT («goto is a keyword and not a valid variable name»). Ключ надо
  закавычивать: `{ ["goto"] = ... }`. Это реально ломало загрузку модуля работ.

## 8. Грабли среды (выстрадано)

- `/tmp` стирается между ходами; `/home/user` вне репо откатывается;
  несуществующий cwd в shell молча затыкает вызов.
- GitHub временами нестабилен (503), и `raw.githubusercontent.com` может не
  отвечать отдельно от основного API.
- Для скачивания архивов мимо GitHub — поднять локальную раздачу:
  `python3 -m http.server 8080` в каталоге `dist/`.
- LuaJIT для стенда собирается с нуля (см. старые сессии).

## 9. Уроки кода (главные, НЕ повторять ошибки)

1. **Никогда не парсить JSON с ключами-SteamID64 голым `util.JSONToTable`** —
   третий аргумент обязателен `(txt, false, true)`; иначе числовые ключи
   калечатся. Корневая причина многонедельной саги потерь денег.
2. Где можно — хранить данные **массивами записей**, а не картами с числовыми ключами.
3. Каждая запись на диск печатает причину (`SAVE ok ... [причина]`), при
   загрузке — «рентген» содержимого.
4. В GMod `file.Write` возвращает nil — контроль записи только read-back.
5. `file.Write` не подтверждает успех — считать сохранение успешным только
   после read-back + повторного decode.
6. Повреждённый JSON не перезаписывать — сначала карантинная копия.
7. Каждый C→S receiver должен быть обёрнут в `GRM.Net.Guard` (rate/size/дистанция/capability).
8. Окно UI — через `GRM.UI.Track(key, panel)` (singleton lifecycle), callback
   очищает/проверяет panel до синхронного rebuild.

## 10. Производительность (что уже оптимизировано и чего избегать)

- `ents.FindByClass` в покадровых хуках — главный источник микрофризов. Там, где
  можно, обёрнуто в `GRM.Perf.Entities(class)` (кэш по `OnEntityCreated/EntityRemoved`).
- `broadcastFactionData()` (полный ресинк всех фракций всем клиентам) —
  коалесцирован в один пакет за тик.
- `ShouldCollide` хук вызывается для КАЖДОЙ пары каждый тик — всегда делать
  ранний выход при пустой таблице пар.
- `Material()` в HUDPaint — кэшировать, а не создавать каждый кадр.
- Полный аудит: `PERFORMANCE_AUDIT_2026.md` (в основной ветке репозитория).
